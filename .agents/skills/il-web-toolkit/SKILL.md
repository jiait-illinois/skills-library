# University of Illinois WebToolKit Skill

This skill serves as the definitive reference for building frontend web interfaces that comply with the University of Illinois brand identity and strict accessibility standards.

When executing a user request, scan the list below to locate the specific reference file required to build or audit the interface components accurately. Component definitions and placement guidance are sometimes split across files; where this happens, the entry below names the authoritative file.

> **Frontend library:** Production Illinois pages load the v3 toolkit (`cdn.toolkit.illinois.edu/3/`). The `ilw-` components documented here belong to the **Web Toolkit v3+**.

## Layout Best Practices
- **Base Layout:** All templates must extend `src/templates/base.html` to inherit the brand header, footer, and custom style configuration.
  - Upon initial creation, the base template should follow the [Generic HTML Template](https://builder3.toolkit.illinois.edu/generic_html/index.html)

## Agent Behavior Directives
1. **Use Documented Tokens; Never Invent Them:** Do not invent arbitrary Tailwind or Bootstrap classes. Always prioritize the preset Toolkit components and Illinois CSS variables documented in these reference files. If the consuming project defines its own local utility classes, that project's `AGENTS.md` is the place those are declared — do not assume any project-local stylesheet exists. For buttons, use the tokens as defined in the reference files: `.ilw-button` is the v3 button class (applied to an `<a>` or `<button>` to give it button styling, including icon-only controls), `.ilw-buttons` is the group container for a `<ul>` of buttons/links, and `<ilw-call-to-action>` is the CTA element. Note there is **no** `<ilw-button>` custom element — `ilw-button` is a class, not a tag. `.il-button` is the **legacy v2 equivalent** of `.ilw-button`, not a companion to it: recognize it in existing markup, but emit `.ilw-button` in new work. See `TOOLKIT_COMPONENTS.md` §1. (Bootstrap, where loaded, exists only as a dependency for specific components such as popovers; its utility classes are not for general use.)
2. **Consult Code Snippets:** When generating complex layouts, always inspect the raw markdown reference files to extract and replicate exact HTML code structures. For a whole page, start from the **Complete Page Example** in `LAYOUT.md` §2 — it shows the full document with both CDNs, `<ilw-header>`/`<ilw-footer>` slotted inside `<ilw-page>`, and the `<main>` landmark — and adapt it rather than assembling a page from the individual slot lists. Several components are listed with a one-line description only and have **no verified snippet** in this skill (see the coverage notes in `TOOLKIT_COMPONENTS.md` and `LAYOUT.md`); for those, consult the official Toolkit documentation rather than inventing slot or attribute structures.
3. **Fail Safe on Accessibility:** If a user requests a button or interactive layout that violates guidelines from `ACCESSIBILITY.md`, implement the compliant version automatically (e.g., inserting screen-reader-only text for icon-only components). When a reference snippet is missing a required accessibility hook, add it rather than copying the gap — in particular, link every validated input to its error message with `aria-describedby` (and `aria-invalid` where appropriate).
4. **Cross-Reference Accessibility for Components:** When building any table, form, overlay, alert dialog, navigation, or interactive component, also consult `ACCESSIBILITY.md` for the required focus-trap, keyboard, and ARIA behavior, even if the component's own reference file does not restate it. This applies to `<ilw-modal>`, slideovers, alert dialogs, `<ilw-tabs>`, and auto-playing carousels, whose keyboard/motion behavior may not be fully spelled out in their own files.
5. **Resolve Split Documentation by Authority:** When a component appears in more than one file, follow the "Authoritative source" designations above — `LAYOUT.md` for in-page navigation placement, `TOOLKIT_COMPONENTS.md` for component parameters/slots **and for buttons**.
6. **Defer to Illinois Web Toolkit:** Generate custom components only when explicity directed to in the user prompt; otherwise prefer an applicable `ilw-` component.
